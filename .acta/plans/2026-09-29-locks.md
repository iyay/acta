# Private Lock Folder and Locked Writes Implementation Plan

> **For agentic workers:** run this plan with acta:build, task by task. Steps use checkbox (`- [ ]`) syntax, and acta reads those boxes as task progress.

**Goal:** Move the lock folder out of shared `/tmp` into the user's own cache folder, lock the debt append and the agent record, and keep the agent name on a nameless start.

**Architecture:** `internal/write/tick.go` gets one function that finds the lock folder (with a test override). `appendDebt` and `RecordAgent` call the existing `lock(path)`. `RecordAgent` keeps the old name when the new one is empty.

**Tech Stack:** Go stdlib (`os.UserCacheDir`, `syscall.Flock`), `internal/write`.

**Spec:** `.acta/specs/2026-09-29-locks-design.md`

## Global Constraints

- Implement ponytail-lazy: YAGNI, then existing code, then stdlib, then native, then an installed dependency, then one line, then the minimum; never cut validation, security or accessibility.
- Security: the lock folder is never under a folder other users can write to, and there is no fallback to `/tmp`. `safeDir` keeps all three checks (real folder, owned by this user, mode closed to others).
- Messages, verbatim: `cannot find a cache folder for the lock: <err>`; `lock folder <dir> is not a folder`; `lock folder <dir> is not owned by you`; `lock folder <dir> is open to other users`; `plan <path> is locked by another acta tick`.
- No test touches the real home or the real cache folder.
- Comments in plain English a 10-year-old can read; say why, not what.
- Gates: `gofmt -l .` prints nothing, `go vet ./...` is ok, `go test ./...` is green.

  - `useLockBase(t)` in `tick_test.go` keeps its name, sets `lockRoot` to a fresh `t.TempDir()` subfolder, and returns that folder.

Review round 1 BLOCKER (Spec axis, security): `internal/write/tick.go` `lockDir` never checks that `os.UserCacheDir()` returned an absolute path. Proof: `HOME=rel go run` of `os.UserCacheDir()` on darwin prints `"rel/Library/Caches" <nil>`. `lock()` then runs `MkdirAll("rel/Library/Caches/acta", 0700)` relative to the working folder. Run from `/tmp`, another user can create `/tmp/rel/...` first, own the parent of `locks`, and swap it; `safeDir` checks only the last folder. Expected: refuse with the cache-folder message.

Round 1 NOTE folded in (test tooling, Global Constraint "No test touches the real home or the real cache folder"): `go test ./internal/write/` made 9 and `./internal/cli/` made 4 `acta-*.lock` files under `$HOME/Library/Caches/acta/locks`, because only some tests call `useLockBase`.
