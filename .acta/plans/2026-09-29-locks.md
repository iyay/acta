# Private Lock Folder and Locked Writes Implementation Plan

> **For agentic workers:** run this plan with acta:build, task by task. Steps use checkbox (`- [ ]`) syntax, and acta reads those boxes as task progress.

**Goal:** Move the lock folder out of shared `/tmp` into the user's own cache folder, lock the debt append and the agent record, and keep the agent name on a nameless start.

**Architecture:** `internal/write/tick.go` gets one function that finds the lock folder (with a test override). `appendDebt` and `RecordAgent` call the existing `lock(path)`. `RecordAgent` keeps the old name when the new one is empty.

**Tech Stack:** Go stdlib (`os.UserCacheDir`, `syscall.Flock`), `internal/write`.

**Spec:** `.acta/specs/2026-09-29-locks-design.md`

## Global Constraints

- Implement ponytail-lazy: YAGNI, then existing code, then stdlib, then native, then an installed dependency, then one line, then the minimum; never cut validation, security or accessibility.
- Security: the lock folder is never under a folder other users can write to, and there is no fallback to `/tmp`. `safeDir` keeps all three checks (real folder, owned by this user, mode closed to others).
- Messages, verbatim: `cannot find a cache folder for the lock: <err>`; `lock folder <dir> is not a folder`; `lock folder <dir> is not owned by you`; `lock folder <dir> is open to other users`; `plan <path> is locked by another acta tick`.
- No test touches the real home or the real cache folder.
- Comments in plain English a 10-year-old can read; say why, not what.
- Gates: `gofmt -l .` prints nothing, `go vet ./...` is ok, `go test ./...` is green.

### Task 1: Lock folder in the user's cache folder

**Files:**
- Modify: `internal/write/tick.go`
- Test: `internal/write/tick_test.go`

**verify:** No path lets a lock land in a folder another user can create, own or open, and every refusal names its reason and takes no lock. Enumerate every path checked (cache folder found, cache folder not found, lock folder missing, lock folder a plain file, a link, mode 0755, owned by another user by code reading, the normal case) with its result, and report the list.

**Interfaces:**
- Consumes: `lock(plan string) (func(), error)`, `safeDir(dir string) error`, `lockPath(plan string) (string, error)`.
- Produces:
  - `var lockRoot string`: test override; empty means use the cache folder.
  - `func lockDir() (string, error)`: `lockRoot` when set, else `filepath.Join(os.UserCacheDir(), "acta", "locks")`; an error from `os.UserCacheDir` comes back as `cannot find a cache folder for the lock: <err>`.
  - `lockPath` returns `filepath.Join(<lockDir>, "acta-"+<16 hex>+".lock")`.
  - `useLockBase(t)` in `tick_test.go` keeps its name, sets `lockRoot` to a fresh `t.TempDir()` subfolder, and returns that folder.
  - `lock` makes the parent of the lock folder with `os.MkdirAll(..., 0o700)` before `safeDir`.

- [ ] **Step 1: Write the failing tests** in `internal/write/tick_test.go`:
  - `TestLockDirIsInTheCacheFolder`: with `lockRoot = ""`, set `HOME` and `XDG_CACHE_HOME` to a temp folder with `t.Setenv`; `lockDir()` is inside that folder and ends in `acta/locks`.
  - `TestLockFailsWithNoCacheFolder`: `lockRoot = ""`, `t.Setenv("HOME", "")`, `t.Setenv("XDG_CACHE_HOME", "")`; `lock(plan)` returns an error starting with `cannot find a cache folder for the lock:` and no lock file exists anywhere under the test's temp folders.
  - `TestSafeDirNamesEachRefusal`: a plain file gives `is not a folder`; a link to a folder gives `is not a folder`; a folder with mode 0755 gives `is open to other users`. Each refusal leaves no lock file.
  - `TestLockFileIsNamedActa`: after `lock(plan)` with `useLockBase`, the one file in the folder matches `^acta-[0-9a-f]{16}\.lock$`.
  - Update the existing test at the line that builds `pmb-<uid>` to use the new folder.

- [ ] **Step 2: Run** `go test ./internal/write/ -run 'LockDir|LockFails|SafeDir|LockFileIsNamedActa' -v`. Expected: FAIL, `undefined: lockDir` or wrong folder.

- [ ] **Step 3: Implement** `lockRoot`, `lockDir`, the new `lockPath` name, `MkdirAll` of the parent with 0o700, the three `safeDir` messages, and the `acta tick` wording in the timeout message. Update the `lockBase` comment block to say why the cache folder is safe (inside the user's home, so no one else can create it first).

- [ ] **Step 4: Run** `go test ./internal/write/ -v`. Expected: PASS, every older write test included.

- [ ] **Step 5: Gates and commit.**

```bash
gofmt -l . && go vet ./... && go test ./...
git add internal/write/tick.go internal/write/tick_test.go
```

### Task 2: Append debt under the lock

**Files:**
- Modify: `internal/write/ops.go` (`appendDebt`)
- Test: `internal/write/debt_test.go`

**verify:** No mix of `acta debt new` appending and `TickLine` ticking on one debt file, in any order or at the same time, loses a change or leaves a half-written file. The append reads the file again under the lock, so a tick that landed after the caller's first read is kept. Enumerate each order checked (append then tick, tick then append, both at once, append with nothing new) with the file afterwards, and report the list.

**Interfaces:**
- Consumes: `lock(path string) (func(), error)` and `useLockBase(t)` from Task 1.
- Produces: nothing new.

- [ ] **Step 1: Write the failing test** `TestAppendDebtAndTickLineKeepBoth` in `internal/write/debt_test.go`, with `useLockBase(t)`: a debt file with one open box; start `TickLine` on that box and `appendDebt` of a new NOTE from two goroutines at once, many times in a loop (for example 50 rounds on fresh files); after each round the file has the first box ticked and the new NOTE present. Also a case where the caller's `src` is stale: tick the box first, then call `appendDebt` with the old `src`; the tick must survive.

- [ ] **Step 2: Run** `go test ./internal/write/ -run TestAppendDebtAndTickLineKeepBoth -race -v`. Expected: FAIL (a lost tick or a lost NOTE).

- [ ] **Step 3: Implement.** In `appendDebt`, take `lock(path)`, read the file again, work out the lines to add from that fresh copy, write to `path + ".tmp"` and rename, then unlock before the commit step.
