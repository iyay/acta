# acta init sets up a new repo

**Goal:** One command, `acta init`, gives a new git repo the `.acta` folder and the acta block in CLAUDE.md or AGENTS.md in one commit, asking nothing.

**Spec:** `.acta/specs/2026-11-24-acta-init-design.md` (SPC-0220)
**Tests:** fast `scripts/test ./internal/setup ./internal/cli ./internal/plugincheck ./internal/hook`; full `scripts/test --full`.
**Gates:** eval: `scripts/eval`; runs when the diff touches `plugin/skills/` or `plugin/hooks/`; narrow form `scripts/eval --tag=<skill folder>` for each skill folder touched and `scripts/eval --case <name>` for one case; whole when the diff touches `plugin/hooks/` or `plugin/references/`. This plan adds `plugin/skills/init/`, so the gate runs as `scripts/eval --tag=init`.

## Global Constraints

- Follow acta:lean: understand the task and the code first; then skip it, reuse code here, stdlib, a native feature, an installed dependency, one line, the minimum; never cut validation, security or accessibility.
- A red test is a new row in an existing table test, else an assert in the nearest test of the same unit; a new test func only for a behaviour no test checks yet.
- Tests that write run in a temp git repo with a temp HOME, never the real one.
- init never folds into HEAD: one changed path goes through `gitc.Commit`, more go through `gitc.CommitPaths`.
