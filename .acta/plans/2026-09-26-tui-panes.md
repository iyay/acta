# TUI panes Implementation Plan

> **For agentic workers:** run this plan with pm:build, task by task. Steps use checkbox (`- [ ]`) syntax, and pmb reads those boxes as task progress.

**Goal:** The TUI shows three numbered panes (`[1]` open items, `[2]` finished items, `[3]` detail) with lazygit-style tabs in the border titles (Specs, Plans, Tasks, Bugs), visible focus, two-line rows with the agent working on each task, a scrollable aligned detail pane, a bottom-right status line with the clock, a `?` popup, and mouse support.

**Architecture:** `internal/board` gains a `plan` kind so every plan file is its own item (a plan with a spec links to it instead of folding into it) and an `Agent` field filled from git-ignored `<root>/.agents.json` files that `pmb tick` writes. `internal/tui` replaces its one-list model with a pane/focus/tab model and a three-pane view; `cmd/pmb` turns on mouse input.

**Tech Stack:** Go 1.27, Bubble Tea v1.3.10, lipgloss, glamour (already direct deps). No new dependency.

**Spec:** `.pm/specs/2026-09-26-tui-panes-design.md`

**Worktree:** `/Users/iyay/Nayakatara/pm-board-tui-panes`, branch `tui-panes`, parent `main` (spec committed; main merged in at 2945fbf).

## Global Constraints

- Values verbatim from the spec: left column 30% of the width, at least 28 and at most 48 columns; pane `[1]` about two thirds of the left height, `[2]` one third, each at least 5 rows; below 60 columns only the focused pane shows; tabs switch with plain `]` and `[`; `1 2 3` focus panes; `tab`/`shift+tab` cycle focus; `a` is removed; status line `pmb · <repo> · live|paused · HH:MM` bottom right; detail labels upper case padded to one width with colons in one column, ID first.
- Agent record file: `<root>/.agents.json`, git-ignored, `{"<task path id>": {"agent": "<name>", "at": "<RFC3339>"}}`; agent from `AI_AGENT` (`claude-code_...` becomes `claude`) or `--agent <name>`.
- Gate before every commit: `test -z "$(gofmt -l .)" && go vet ./... && go test -count=1 ./... && (cd plugin && bun test)`.
- Edit only the files each task names. Stage by path. Never push. Never commit the plan file. gofmt inside the task commit. Tests use fixtures as they are; never delete fixture files to pass. A defect in code this branch added is fixed in this branch, never filed under `.pm/bugs/`.
- Comments in plain English a ten-year-old can read, saying why. No marker tags.
- Implement ponytail-lazy: YAGNI, then existing code, then stdlib, then native, then an installed dependency, then one line, then the minimum; never cut validation, security or accessibility.
