### 2026-10-04

Approach (2026-10-04): B, path hints. Session start adds one line. When the agent reads or edits a file, or a Bash command names a path, that falls under a page's paths:, the PreToolUse hook adds one line naming the page. Each page shows once per session. Picked over A (catalog at start, cost grows with the page count) and C (workflow only, misses ad-hoc work and debugging).

### 2026-10-04

S1 approved (2026-10-04), page format. Pages live in .acta/wiki/, under the acta root, one concept per file, subfolders allowed, id = path minus .md. Fields: type, title, description, timestamp from OKF, plus paths. tags is dropped. paths lists files or folders from the repo root; a folder ends with /; matching is by prefix with no globs; paths may be empty. timestamp is ISO 8601 with time and is bumped on every change or re-check. Five types: Decision (covers ADR and Convention), Gotcha, Runbook (covers Playbook), Reference (covers Architecture), Glossary (one glossary.md, replaces CONTEXT.md). description is one line of about 120 chars at most, since it is the hint text. The body is 250 words at most; split longer pages and link them. There is no index.md and no log.md: acta wiki ls builds the list and git keeps the history. A repo with no .acta/wiki/ has the feature off and pays 0 tokens. The board reads only the folders it knows, so it skips the wiki with no change.

### 2026-10-04

S2 approved (2026-10-04), reading path. 1) Session start adds about 50 tokens, the same at any page count, only when .acta/wiki/ has pages: the page count, read the page a wiki: line names before changing its files, and project knowledge goes to the wiki, not agent memory. 2) The PreToolUse matcher widens from Bash to Bash|Read|Edit|Write|MultiEdit. acta hook pre-tool matches the file path, or the words of a Bash command with ./ and /... stripped, by prefix against every page's paths, and prints one line: wiki: <path>: <description>. A hint always exits 0. 3) Each page shows once per context. Pages already shown are kept in .acta/state/ (gitignored) per session, and that list resets after compaction. Open, first plan task: check whether subagent hook input carries the parent's session_id. If it does, the key needs a field that tells contexts apart. 4) omp: whether tool_call or tool_result can add text is not known; the first plan task probes it. Fallback: the dispatch brief carries acta wiki match output for the plan's files. 5) acta:shape reads glossary.md and acta wiki ls --type Decision before its questions; new terms and decisions are proposed as pages, with the same yes gate. No per-prompt text is added. description must carry the key fact.

### 2026-10-04

S3 approved (2026-10-04), writing path and commands. 1) Pages are written in the last step of build, before review, by the agent that ran the plan (main agent, or omp under dispatch). It runs acta wiki check <parent>..HEAD, re-checks each page whose paths the branch touched (fixes wrong lines, bumps timestamp), and adds a page only for a lesson a fresh agent would lose time without. One commit in the worktree. There is no wiki task in plans. 2) The commands are read-only and never commit: acta wiki ls [--type T]; acta wiki match <file>... (same code as the hook); acta wiki check [<range>], which reports missing or bad fields, an unknown type, a description too long, a body over 250 words, paths that do not exist, and stale pages. With a range it checks only pages the range touched. It exits 1 on problems. 3) acta:land runs acta wiki check <parent>..HEAD with the other gates; problems block the merge. The landing report lists wiki pages added or changed. 4) The format and writing rules live in plugin/skills/build/wiki.md, read from build's last step and from shape. 5) A page is written at most once per plan, edits change lines instead of rewriting the page, and nothing git, plans or debt already hold gets a page. MVP limit: sessions with no build (Q&A, investigation) write no pages, since the main checkout is read-only for agents. Their findings go to scratch or bug items first.

### 2026-10-04
